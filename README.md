# CSAT ML Assistant: автономный Telegram-бот поддержки с циклом самообучения

Проект Telegram-бота поддержки по основам машинного обучения (ML) со встроенным сбором пользовательских оценок (CSAT, Customer Satisfaction Score) для непрерывного улучшения модели на зафиксированных ошибках.

---

## Архитектура и принцип работы

Бот построен по принципу замкнутого маховика данных (Data Flywheel):
1. **Запрос:** пользователь задает вопрос по машинному обучению в Telegram.
2. **Инференс:** локальная языковая модель через `proxy.py` формирует краткий ответ по теме (метрики, алгоритмы, валидация).
3. **Оценка (CSAT):** к каждому ответу бот прикрепляет инлайн-кнопки («👍 Помогло» / «👎 Не помогло»).
4. **Сбор телеметрии:** нажатия логируются в `feedback_log.jsonl` с сохранением вопроса, сгенерированного ответа, ID пользователя и метки (1 / 0).
5. **Дообучение:** вопросы с негативными оценками формируют целевую выборку для следующей итерации LoRA-дообучения.

## Выводы эксперимента: почему 0.5B параметров мало

В качестве экспериментальной базы исследовалась модель `Qwen2.5-0.5B-Instruct`, дообученная с помощью LoRA на 769 аутентичных русскоязычных примерах (`mlcourse.ai` OpenDataScience, главы технической литературы, академический словарь ИИ).

### Результаты тестирования
- **На развернутых вопросах (бенчмарк 100 вопросов):** модель показала среднюю точность `0.737` / 1.000, успешно воспроизводя канонические определения (L1/L2 регуляризация, специфика ROC-AUC при дисбалансе, свойства Random Forest).
- **В реальном диалоге с короткими репликами:** на запросах из 2-3 слов («что такое бэггинг?», «градиентный бустинг?») архитектура 0.5B ведет себя не как логический ассистент, а как ассоциативная память. Из-за нехватки емкости весов она цепляется за поверхностные шаблоны словаря и начинает выдавать случайные словарные статьи или ложные отказы.
- **Влияние квантования:** динамическое INT8-квантование на моделях размером 0.5B с огромным словарем (152 000 токенов) сжимает логиты и дополнительно деградирует распределение вероятностей.

### Рекомендация для продакшена
Для стабильной диалоговой поддержки рекомендуется использовать модель **минимум на 1.5 млрд параметров** (например, `Qwen2.5-1.5B-Instruct` или 3B) в точности FP16/FP32 либо с минимальным квантованием (AWQ / GPTQ вместо грубого dynamic INT8). Модели от 1.5B параметров существенно лучше удерживают контекст и понимают короткие формулировки.

## Структура проекта

```text
├── bot.py                  # Основной процесс Telegram-бота (aiogram 3, очередь инференса, CSAT)
├── proxy.py                # Модуль инференса (загрузка модели, chat template, генерация)
├── train_lora.py           # Скрипт дообучения LoRA с защитой от отсутствия весов
├── merge_and_export.py     # Слияние весов LoRA с базой и экспорт в ONNX FP32
├── export_and_quantize.py  # Автономный конвертер моделей в формат ONNX
├── validate_dataset.py     # Валидатор токенизации и длин примеров в датасете
├── dataset_ml_support.jsonl# Обучающая выборка по машинному обучению (769 строк)
├── benchmark/              # Набор тестов на 100 вопросов и скрипт скоринга
├── weight_model/           # Директория для локального размещения весов базовой модели
└── .env                    # Переменные окружения (токен бота, прокси, путь к модели)
```

## Быстрый старт

### 1. Установка окружения

Требуется Python 3.10+:

```bash
pip install torch transformers peft optimum onnxruntime aiogram python-dotenv datasets
```

### 2. Конфигурация (.env)

Создайте в корне проекта файл `.env`:

```env
BOT_TOKEN=ваш_токен_telegram_бота
# Опционально: если Telegram заблокирован провайдером
TELEGRAM_PROXY=http://127.0.0.1:10809
# Опционально: переопределение модели (по умолчанию Qwen/Qwen2.5-0.5B-Instruct)
MODEL_PATH=Qwen/Qwen2.5-1.5B-Instruct
```

### 3. Запуск бота

```bash
python bot.py
```

Модуль `proxy.py` автоматически проверит доступное железо:
- Если доступна видеокарта с CUDA, модель запустится в `float16`.
- На CPU инференс будет запущен в `float32`.
- Если локальная папка `weight_model/` пуста, бот автоматически подтянет веса из Hugging Face.

## Дообучение собственной модели

Вы можете подключить любую собственную LLM вместо дефолтной.

### Шаг 1. Размещение весов
Поместите файлы вашей модели и токенизатора в папку `weight_model/` либо скачайте рекомендованную базу:

```bash
huggingface-cli download Qwen/Qwen2.5-0.5B-Instruct --local-dir weight_model
```

### Шаг 2. Проверка датасета
```bash
python validate_dataset.py
```

### Шаг 3. Запуск LoRA
```bash
python train_lora.py
```
Обученные веса адаптера будут сохранены в папку `lora_output/`.

### Шаг 4. Слияние весов и экспорт в ONNX
```bash
python merge_and_export.py
```
Скрипт объединит веса адаптера с базовой моделью в `merged_model/` и экспортирует ее в `onnx_model_new/model.onnx`.

## Формат лога телеметрии CSAT

Все нажатия кнопок пользователями записываются в `feedback_log.jsonl`:

```json
{
  "timestamp": 1789944402,
  "user_id": 5887558719,
  "question": "что такое бэггинг?",
  "answer": "Бэггинг — метод ансамблирования, где несколько базовых моделей обучаются независимо...",
  "score": 1,
  "feedback": "like"
}
```

Строки с `"score": 0` используются для генерации исправленных ответов и пополнения датасета для последующих релизов.
