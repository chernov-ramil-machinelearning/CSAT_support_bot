# self-improving-csat-bot

Telegram-бот с непрерывным дообучением: RAG-поиск по документации + генерация ответа моделью Qwen 0.6B, качество которой со временем растёт за счёт CSAT-оценок пользователей.

## Идея

Обычный RAG-бот статичен: как настроили ретрив и генерацию, так и работает. Здесь генератор продолжает дообучаться на реальном фидбэке, а ретрив со временем начинает учитывать, какие документы реально приводили к хорошим ответам — а не только косинусное сходство.

## Архитектура

| Файл | Роль |
|---|---|
| `bot.py` | Telegram-интерфейс: принимает вопрос, вызывает `proxy.py`, отправляет ответ с кнопками оценки, пишет событие и CSAT-оценку в лог |
| `proxy.py` | Ретрив (top-k чанков с учётом текущих весов) + генерация ответа (Qwen 0.6B + LoRA-адаптер) |
| `train.py` | Запускается отдельно (по расписанию / после N новых оценок): читает лог и агрегаты, обновляет веса чанков и/или дообучает LoRA-адаптер |
| `test.py` | Независимая оценка текущей версии модели на held-out наборе — не участвует в живом цикле |
| `config.py` | Общие пути к файлам состояния — единственное место, откуда их берут все скрипты |

### Данные / состояние

- **лог событий** (`feedback_log.jsonl`) — append-only: `message_id`, использованные `chunk_id`, оценка
- **агрегаты по чанкам** (`chunk_scores.json`) — скользящий скор качества на чанк, читает `proxy.py`, пишет `train.py`
- **LoRA-адаптер** — отдельная папка на диске, `train.py` пишет новую версию, `proxy.py` подхватывает при следующем запуске

Никакой БД — для личного проекта такого масштаба это лишняя сложность.

### Два независимых цикла

**Живой** (на каждый запрос): пользователь → `bot.py` → `proxy.py` (ретрив + генерация) → ответ с оценкой → лог.

**Периодический** (по расписанию, отдельно): триггер → `train.py` читает лог → обновляет веса чанков и адаптер → `proxy.py` подхватывает изменения при следующем запросе.

Эти два цикла не вызывают друг друга напрямую — связь только через файлы.

## Тематика

Узкая проверяемая ниша: FAQ/техподдержка по документации собственных проектов — есть готовый контент и объективная правда для held-out теста, не нужно придумывать датасет с нуля.

## Roadmap

- [ ] Этап 1 — эвристическое перевзвешивание чанков по CSAT (без обучения весов)
- [ ] Этап 2 — контрастивное дообучение эмбеддинг-модели на парах (запрос, хороший/плохой чанк)
- [ ] Этап 3 (опционально) — отдельный reranker, если понадобится

## Установка

```bash
git clone <repo>
cd self-improving-csat-bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # заполнить TELEGRAM_TOKEN и т.п.
python bot.py
```
